# AGENTS.md

Chinese herbal medicine short-video production: mobile-first 9:16 Remotion videos built from classical TCM book texts.

## Layout

- The git repo is the **workspace root**: code lives in `remotion-video/`, and the workflow skill, this file, the corpus, the music and the brand assets are tracked alongside it. Run npm commands inside `remotion-video/`; CI does the same via `working-directory`.
- `remotion-video/` — all code work happens here.
- `TCM-Ancient-Books-master/` — read-only corpus of ~700 classical texts (e.g. `000-神农本草经.txt`). **Every file is GB18030, not UTF-8**, so `rg` and any other UTF-8 byte search matches no Chinese at all and reports "not found" for text that is plainly there — search with `npm run entry -- --grep=<词>` instead, which decodes first. Preserve source wording. Read it through `scripts/lib/corpus.ts` (`findEntries` / `sutraOf` / `defectOf` / `originOf`), never by walking lines at the call site: `new-film.ts` did that and read only the first line of each 内容 block, so every entry whose 经文 wraps was scaffolded with a truncated `original`. The recension is damaged in three ways, and only the first two are visible to a reader of it: a sentence **truncated** mid-clause, a character **dropped** (the corpus marks those with an inline space), and a character written **wrong** — 大枣's 「肋十二经」 for 「助十二经」 reads as valid Chinese, so no gap marks it and only `npm run variants` finds it by comparing recensions. Tracked, because `progress.json` and every 今译 are derived from it.
- `.agents/skills/herbal-short-video-production/SKILL.md` — authoritative production workflow. Load the `herbal-short-video-production` skill before any video work; its rules (mode/seal, 今译 vs 注释, content-repetition, platform copy, verification order) override defaults.
- `music/` — source mp3s (Chinese filenames). Sync into `remotion-video/public/music/` under ASCII names via `npm run sync-music` (see `scripts/sync-music.mjs`); only those ASCII names exist at render time. The same command writes `remotion-video/src/music-registry.ts`, which records each track's length, head silence and source. The length is load-bearing: `@remotion/media`'s `loop` derives the loop length from `trimAfter` and treats unknown media as infinite, so a film-length `trimAfter` makes `loop` silently play the track once — which is how `out/tu-que-h.mp4` shipped with its last 1:46 playing against digital silence.
- `sign-1.png` — brand seal asset, duplicated into `remotion-video/public/`.
- `v2-858c5bf7e3c2516f6993f74a5140169d_b.jpg` — scanned 神农本草经 title page, used as a visual reference for paper texture and typography rhythm. Its provenance is unrecorded, so never place it in a film.
- `remotion-video/progress.json` — original-order coverage ledger for the current book (rebuild via `npm run progress`); next film = first `todo` entry.
- `remotion-video/docs/longform.md` — **长视频《一句话的旅行》制作手册**（16:9，镜头清单驱动），跨书专题线的现形态：内容仍是 `src/topics/<id>/`，只是从手写 `.ts` 换成了 `film.yaml` + 编译出的 `film.json`（旧一期 `tu-que` 是它的上一版）。做长视频先读它：`longform:voice` → `longform:build` → `longform:sheet` → render；金样例是 `src/topics/pangxie/`。镜头组件在 `src/longform/`，不要在 film.yaml 之外为单期片子写 JSX。
- `.github/workflows/ci.yml` — runs from the repo root with `working-directory: remotion-video`.

## Commands (run inside `remotion-video/`)

- `npm run dev` — Remotion Studio preview.
- `npm run longform:voice|longform:build|longform:sheet -- <id>` — 长视频三步：配音（Python edge-tts，产出词级时间戳，只重做改过的段）、校验并编译 `film.json`（引文逐字核对语料、`at` 词换算秒、检索命中数、谱系图自动分道、字数上限、画面静止 ≤ 6.5 秒；FAIL 不出 `film.json`）、渲染联络表（在浏览器里实测出画/压字幕/标签重叠，表头写「版面检查通过」才算过）。规则见 `docs/longform.md`。
- `npm test` — `node --test --experimental-strip-types` over the files listed in `package.json`. `node --test tests/` silently skips the TypeScript files, so the list is explicit and `tests/suite.test.ts` fails if it drifts.
- `npm run lint` — `eslint src && tsc`; run after tests, before rendering.
- `npm run check` — the pre-render gate. It splits into two kinds of finding, because a verdict is only useful when something can still act on it. **Judgements** (compliance rules, repeated-text scan, the ledger check) decide `ok` / `draft` / `FAIL`, and only `FAIL` exits non-zero. **Facts** (does the 产地 name a place the 经文 names, does the 经文 on screen match the corpus, is the track registered) are computed for *every* film and printed for the ones already live — a published film cannot be un-published, but a wrong fact on it is still a fact about the channel. Hiding those behind an exemption is how 蓝实 and 紫芝 shipped a 产地 their own cited 经文 contradicts while the gate printed `0 gap(s)`.
  A film counts as live when its ledger's 数据回填 table carries a date (`publishedOn`), which `npm run stats` fills from the platform's own export. It is **not** decided by a master sitting in `out/`: rendering is not publishing, and `out/` does not exist in CI, so a disk-based exemption gives the same film two different verdicts on two different machines. The wording rules scan `claimText` — the prose the renderer actually draws (hook, 今译, 注释, 事实条) — and the same one function scans 标题 / 描述 / 话题, because the platform acts on the copy. Quotations are excluded: the 经文 says 主, and sometimes 主治, and that is the source talking.
  Titles are no longer a gate. Stripping 「」 slots and one interrogative tail missed the case it claimed to catch (古书里的X是什么 and 古书里的Y是什么 come out as two different frames), and whether a sentence is one you have already written is taste — `--verbose` prints every ledger title so the set can be looked at rather than remembered.
- `npm run new-film -- --id=<CompId> [--latin=...] [--entry=...] [--recension=<字> --why=<据何本>]` — scaffold the next `todo` entry: writes the content module, the film file and the upload ledger in one shot (see `scripts/new-film.ts`). The scaffold is a draft by construction. It refuses an entry whose 经文 the recension damaged — see `scripts/lib/corpus.ts` — unless the caller names the witness reading for a dropped character (`--recension`) and says which witness it is (`--why`); both are required together, and the correction is written into the content module's header and the ledger's 备注 so a restored character always carries its provenance.
- `npm run entry -- --name=<条目> | --list [--fits] | --grep=<词>` — read one entry's 经文 out of the corpus, measure it against the duration budget, and report the two defects that make it unquotable (a 经文 truncated mid-sentence, or a character the recension dropped — the corpus marks those with a space). `--grep` is the only search that works on this corpus.
- `npm run variants [-- --all]` — compare the 底本 with 《证类本草》 entry by entry and report the single-character disagreements the corpus backs on one side only. This catches the *third* defect class, a 讹字: a character the recension got **wrong** rather than dropped. `corpus.ts` cannot see it, because 「肋十二经」 for 「助十二经」 reads as valid Chinese and leaves no gap to find. It reports and never fails — deciding 讹字 vs 古今字 is a judgement about the word, and the flagged set is small enough to read (24 of 434 disagreements).
- `npm run fetch-photo -- --taxon="<Latin name>" --file=<stem> [--check] [--list=N] [--fruiting] [--id=<photoId>]` — fetch an open-licensed iNaturalist photo into `public/images/` and register it in `credits.json` in one step. `--fruiting` filters to observations annotated as fruiting, which is the only signal that says the fruit is in the frame: the default ranking sees orientation, resolution and licence, and for 龙眼 the top ten were all leaves.
- `npm run gen` — regenerate `src/Composition.tsx` from `src/finished/` (see `scripts/generate-compositions.mjs`). Drafts are skipped, so a half-finished film never becomes renderable.
- `npm run verify -- --film=<CompId>` — runs the rule check as a pre-flight, then hero/source/closing stills to `out/films/stills/`, renders `out/films/<name>.mp4`, and asserts 1080x1920 / 30fps / H.264 / AAC / duration / file size via ffprobe (see `scripts/verify-film.mjs`). It also decodes the audio and fails a film whose music stops before the film does — ffprobe reports the stream, not the samples, so a healthy AAC stream over a dead bed passed every check until `scripts/lib/audio.ts` looked at the samples. Add `--sheet` for a contact sheet. Refuses to render a draft.
- `npm run topic:verify [-- --topic=<slug>] [--verbose]` — the same idea for the long-form cross-book series in `src/topics/`, which renders through `TopicFilm` rather than `EntryFilm` and had no verification at all. `--verbose` prints where the silence is, which is the question that matters for a film with a loop seam in the middle.
- `npm run progress` — rebuild `progress.json`; per-book config lives in `scripts/books/`. A data-driven film's entry→id mapping is derived from its own content module, so a new film needs **no** book-config edit; the config's `done` map is now a legacy supplement for the 55 hand-written films.
- `npm run manifest` — refresh `masters-manifest.json` (which masters exist and their sizes).

## Conventions

- **A gate rule must bind to behaviour, not to a field's shape.** The seal rule used to validate `mode` while the renderer hardcoded `药`, so `mode: "formula"` passed and still drew 药. Anything the gate checks has to change what a viewer sees; if it cannot, either wire it up or drop it. Mappings that the renderer reads (e.g. `SEAL_GLYPH` / `sealGlyph(mode)` in `src/layout.ts`) are preferred over inline literals, because a `Record<mode, …>` makes a missing case a compile error instead of a silent fallback.
- **…and a semantic rule must reject its opposite.** `hasHistoricalFrame` was three independent regexes over the whole note, so 「汉代旧说，未经证实。现代临床已证实其效」 passed — the era and the denial were there, and so was a clause saying the reverse. Requirements now have to co-occur inside one clause, a clause that *affirms* modern confirmation fails on its own (`affirmingClauses`), and both cases are pinned as bad inputs in the suite. A predicate that only checks for the presence of the right words enforces nothing; the same went for the efficacy-frame rule, which accepted exactly one five-character opener and so made all 19 films begin their 今译 identically — `FRAME_MARKERS` is a set of wordings now.
- **A new film is data, not JSX.** Content goes in `src/films/<kebab>.ts` (a `FilmContent` object); `src/finished/<kebab>.tsx` is a ~5-line wrapper that renders `<EntryFilm content={content} />`; `src/layout.ts` computes every block's geometry, the scene split, the duration and the pacing; `src/entry-film.tsx` draws it. Never hand-position a block in a film file, and never hand-tune a font size outside `TYPE` in `src/layout.ts` — `npm run check` fails on both.
- **Draft state.** A data-driven film whose content module still carries `TODO` placeholders is a *draft*: `npm run check` reports it, `npm run gen` does not register it and `npm run verify` refuses to render it. That is what makes the gate's leniency towards drafts safe — a draft has no Composition, so it cannot reach a platform. `tests/compliance.test.ts` asserts no draft is ever registered.
- Film shape, pacing, music, and test literals are specified in `SKILL.md` (§ Template And Audio Boundaries, Verification) — follow it, don't duplicate it here.
- **Published films are frozen.** `scripts/lib/frozen-films.ts` lists the 55 films already live on the platforms; the current rules are not re-applied to them and never add a new film to that list. New films must pass `npm run check`. That list is a 2026-09-21 snapshot because the legacy films have no ledgers — there is no other record of what they carried. Films published since do have one: `publishedOn` (`scripts/lib/ledger.ts`) reads the date out of the ledger's 数据回填 table, which `npm run stats` fills from the platform's own export, and treats them the same way. A hand-typed `已发布` line is not a date and a master in `out/` is not a publication — `out/` is gitignored, so a disk-based exemption would give one film a different verdict on every machine that lacks it. Freezing a film means *not failing* it, never *not reading* it: the fact checks still run on all 74 and the live ones are printed.
- **The gate separates safety from budget.** Safety rules — banned efficacy wording, the historical frame, the disclaimer, geometry, the photo, and a screen past `READING_HARD_FLOOR` — have no waiver path, and that is what keeps "anything renderable is compliant" true. Budget rules (`duration`, `reading-budget`, `pacing`) may be waived by a film that records why: `deviations: [{ rule, why }]` in its content module, where `rule` must be in `NEGOTIABLE_RULES` and `why` must be non-empty. A waiver never deletes the finding; it marks it, so `npm run check` prints the film's own reason. **A waiver must have a floor:** naming all three budget rules used to switch the density guard off entirely, and a film shipped a screen at 27 字/秒 with `hardViolations` empty. `unreadable` is a separate, un-negotiable rule for that reason. See SKILL.md § 声明偏离.
- Rule gates live in `scripts/lib/` (`compliance.ts`, `film-rules.ts`, `repeat-scan.ts`, `frozen-films.ts`, `ffprobe.ts`, `film-files.ts`, `film-content.ts`) so tests and CLIs share one implementation. `film-rules.ts` exists because `check` and `verify` each carried a copy of the fact checks and drifted — `verify` rendered a film whose track was missing from `music-registry.ts`, which is precisely the input the silent-`loop` bug needs. If a rule is implemented twice it is half-enforced. `tests/compliance.test.ts` proves the checker fails on bad input before it is trusted.
- `HerbalFeature`, `HerbProfileTemplate` and `FormulaShortTemplate` in `src/HerbalVisuals.tsx` are legacy scaffolding: no finished film references them. Do not build a new film on them.
- Shared shell: `src/herbal-stage.tsx` (`SceneShell`, `Seal`, palette), `src/herbal-cards.tsx` (`fade`, `rise`) and `src/finished-shell.tsx` (`FinishedFilm`, `FinishedMusic`). Extend these only backward-compatibly — 55 published films render through them, and a change that alters their output is a regression. After touching one, render a frozen film's still and diff it against the pre-change still (byte-identical md5) before committing.
- `FinishedFilm` takes `breaks: number[]` + `scenes: FinishedScene[]`; the 2-tuple/3-scene form it replaced must stay derivable, and `scripts/verify-film.mjs` samples the hero, the last classical scene and the closing scene from the same plan the renderer uses.
- Assets: photos in `public/images/` with ASCII filenames + a `credits.json` entry, always rendered via Remotion `Img` + `staticFile` — never native `img` or CSS `backgroundImage`; never code-draw herbs. A data-driven film names its photo in the content module, and `tests/finished-video.test.ts` asserts the module's author/licence match the ledger exactly. **Photos are capped at 2000px on the long edge** (`scripts/lib/image.ts`): the insert is 932px wide and the blurred bed is 1080px, but iNaturalist serves research-grade originals — the folder had reached 134 MB with 3248×4872 files, all of which every CI run checks out to render one 12-second film. `fetch-photo` shrinks at the door and the test suite fails an oversize file. The size is read from the JPEG/PNG header, not decoded, because that check runs over all 86 of them.
- Tests live next to the rules they enforce (`tests/layout.test.ts` for geometry, `tests/finished-video.test.ts` tables + sweeps). Add a focused failing test for a new video before implementing. Assert on derived values, not on counts of files or assets — and that includes counts owned by an outside party. `tests/stats-import.test.ts` pinned the 抖音 export at "49 videos plus the header" because the export *is* the fixture; the creator exported again on 10-02 and the suite went red over a fixture change while the parser was fine, and nobody noticed for a day. Where the numbers themselves are the thing under test (a ratio must read as `34.4`, not `0.3` or `343812`), assert them, but assert the structural invariant alongside — every video row is either placed or reported — so the next export does not turn a parser test into a fixture test. Sweeps that treat a file as a shipped film must iterate `renderableFiles` (drafts excluded).
- **每条线各有自己的文件夹，名字与源码那边一致**（`src/films|topics|asks` → `upload/films|topics|asks` 与 `out/films|topics|asks`）。三条线平铺在一个目录里时，新的那条只能靠文件名前缀认出来，而前缀是靠人记得加的——漏一次就混进别人的清单。同名还有一个好处：想找某一集的东西，三处路径可以照着同一个名字敲出来。跨线的记录（`upload/_incidents.md`、`upload/_frozen-disposition.md`）留在 `upload/` 根下，它们不属于任何一条线。
- `out/` is gitignored; render output goes to `out/films/<name>.mp4`（专题线 `out/topics/`，问答线 `out/asks/`）. The masters therefore have no history — `npm run manifest` records all three series separately, and `out/` needs a copy outside Git. Nothing in the gate reads `out/` any more: a local render grants no exemption, and a publication is a date in a ledger.
- Content language is Chinese (STKaiti for classical text); file/code identifiers stay English/ASCII.
- Do not edit the same file with two parallel edits — the second write wins and silently drops the first.
