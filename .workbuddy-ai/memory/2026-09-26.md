### 环境发现（重要）

**本机网络通过代理 `http://127.0.0.1:52928` 出网。** 实测各图源：

| 主机 | 结果 |
|---|---|
| `www.baidu.com` | 200 |
| `api.gbif.org` | 200 |
| `api.inaturalist.org` / `www.inaturalist.org` | 200 |
| `inaturalist-open-data.s3.amazonaws.com` | 200（图片可下载） |
| `upload.wikimedia.org` / `commons.wikimedia.org` | 000 超时 |
| `api.openverse.org` / `images.unsplash.com` | 000 超时 |

结论：**SKILL.md 规定的两个图源（Wikimedia、Openverse）在这台机器上不可达，但 iNaturalist 可以**，且它的 `photos[].license_code` / `attribution` 字段直接给出 CC 授权与作者，完全满足授权登记要求。**新片的配图通道改走 iNaturalist。**

可复现的取图流程：
1. `https://api.inaturalist.org/v1/observations?taxon_name=<属名>&photo_license=cc0,cc-by,cc-by-sa&per_page=40&quality_grade=research&order_by=votes`
2. 取 `photos[0].url`（形如 `.../photos/<id>/square.jpg`），把 `square` 换成 `original` 得原图
3. 用 `public/images/` 里的 ASCII 文件名保存，登记 `credits.json`

另：`tests/finished-video.test.ts` 断言 `credits.json` 的文件列表与 `public/images/` 下的文件**完全一致**，所以不能先登记图片再补文件——必须先有文件。

**看图的办法**：本会话的 Read 工具读不出图片（返回「could not be processed」），用 `node_modules/@remotion/compositor-win32-x64-msvc/ffmpeg.exe` 把图缩成 1×1 再取 RGB，可以判断主色。注意这个 ffmpeg 是精简版：没有 `rawvideo` **muxer**（要用 `-c:v rawvideo -f image2pipe`），也没有 `ppm` 编码器。

### 本轮修掉的三个真缺陷

1. **接续屏的孤立标签**：`planClassicalScenes` 给每个 classical 场景都加了
   `CLASSICAL ENTRY / 古籍原文（续）`，但原文只在第一屏印一次，于是续屏顶上挂着一个下面
   什么都没有的标题。改为续屏用 `MODERN READING / 今译（续）`。
2. **重复扫描看不到多行 JSX**：`extractVisibleText` 的正则排除了 `\n`，而手写影片的文案
   都独占一行，于是 55 部成片的屏幕文案有 ~95% 对它不可见——SKILL.md 声称的「JSX 也会被扫，
   漏写的短语照样抓得到」对最需要它的那些影片不成立。修好后每部片可见字符从 ~97 涨到 ~280–340。
3. **`verify` 在本机跑不动**：它用 `spawnSync` + `npx`，而本沙箱同步派生一律 `EBUSY`
   （异步 `spawn` 正常），`npx` 还要经过 cmd.exe。改为用 `process.execPath` 直接跑已安装的
   Remotion CLI，并全程 await。
