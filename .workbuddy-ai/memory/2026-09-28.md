## 四个真 bug（都不是我改出来的，是本来就在）

1. **语料是 GB18030，`rg` 全线失效**。701 个 txt 全如此，UTF-8 字节匹配零命中，会把「有这一条」报成「没有」。
   `AGENTS.md` / `SKILL.md` / `publish-plan.md` / `MEMORY.md` 四处都写着「用 rg」，全部改正，并给
   `entry` 加了 `--grep`（唯一能搜中文的通道，顺带能跨 701 个文件互证，写注释时很有用）。
2. **`new-film.ts` 只读 `内容：` 的第一行**，于是所有跨行经文都被生成成截断的 `original`
   （决明子被生成为「…益精光（《太平御览》」——读起来像完整句子）。抽出 `scripts/lib/corpus.ts`，
   两个入口共用一份提取逻辑，并在缺字/截断时拒绝生成。
3. **语料有 28 条行内掉字**（底本用空格占位：龙骨「惊痫 疾狂走」、黄连「目痛、 伤泣出」）。
   空格归一化会把缺字粘成通顺句子，比明显空缺更危险。`entry` 现在报「缺字N」并列出上下文。
   检测本身还漏过一版：只认「汉字 空格 汉字」，漏了空格挨着标点的（黄连）。
4. **配图扩展名因图而异**，同桶同许可有的 `.jpg` 有的 `.jpeg`。旧记录写「一律 `.jpeg`」是错的，
   硬编码任一种都静默砍掉一半图库。改为从 API 的 `photo.url` 读扩展名，另一种兜底。
   另加：`--id=` 按 id 取图、3 次退避重试（代理会偶发 ECONNRESET）、`--file` 不再变 `.jpg.jpg`。
