新增三个模块：

  不引第三方依赖。支持 sharedStrings / inlineStr / 数字 / 空单元格，按最宽行补齐。
- `scripts/lib/stats-import.ts`：两个平台归一化到同一形状。注意它们的差异：抖音写比例
  （0.139808），视频号写百分比（"37.93%"）；日期一个 `2026-09-25 08:00:00`、一个
  `2026/08/30`；时长一个 `6.700458`、一个 `7.80秒`。
- `scripts/stats.ts`：`npm run stats -- --file=<导出文件> [--dry-run]`

**行归属靠平台文案里的条目名**——导出里没有影片 ID，而各时期的文案模板一直在变
（「《神农本草经》里的扁青：…」「《神农本草经》如何记载柴胡？」）。做法是取**在文案里出现
最早**的已知条目名（并列时取更长的）。踩过的坑：

1. 只按"最长匹配"会把**朴硝**那行记到**硝石**名下——朴硝的文案里也提到硝石，两者同为
   两字，谁先被遍历到就归谁。改成按出现位置判定。
2. 单字条目（术、黄）太短，不能全文匹配；改为只认文案开头的 `术：`。**黄**另需在
   `scripts/books/shennong-bencao-jing.mjs` 的 `titleAliases` 里声明 `黄: ["黄耆"]`。
3. 新建台账时"内容没变化就跳过写盘"导致文件根本没落盘——要额外判断文件是否存在。
4. 抖音和视频号分两次导入，第一遍会把 `视频号：` 写成"未发布"且第二遍不纠正。
   加 `syncPlatformFields`，从**合并后的表**反推平台状态，与导入顺序无关。
5. `mergeStatsSection` 只返回表格段，传整份台账进去会静默丢掉上面的字段。加了
   `mergeLedgerStats` 作为正确入口。

**为 55 部存量片补建了台账**（`renderPublishedLedger`）：标题/描述/话题/BGM 全部留空
（不可考，不臆造），只记平台状态与数据表。`npm test` 只对**新片**要求台账，所以不冲突。

### 数据结论（重要）

**阅读压力确实预测留存，但只在 9 月这批里清楚**（n=24）：

| 对照 | 相关系数 |
|---|---|
| 阅读压力 vs 2s跳出率 | **−0.013**（无关） |
| 阅读压力 vs 5s完播率 | −0.081 |
| 阅读压力 vs 完播率 | **−0.342** |
| 阅读压力 vs 平均播放时长 | **−0.323** |

分档看平均播放时长单调下降：<20 字/秒 → 7.6s，20–24 → 6.8s，24–28 → 6.9s，>28 → 6.1s。

**关键推论**：阅读压力**不解释**开头的 2s 跳出（23–41%）。伤的是中段留存。开头那四分之一
的流失是封面/标题的问题，跟文字量无关。8 月这批相关性弱（−0.09 ~ −0.19）且 2s 跳出反而
正相关（+0.194），说明有发布时间/选题的混淆。

平台现状：**49 部在抖音、33 部在视频号**，麻黄两边都不在。

**视频号在 08-19 与 08-21 之间断崖**（08-19 菟丝子 1642 播放 → 08-21 起 0–29，且再未恢复），
完播率同期没有变差（木香 37.9%、车前子 31.8%）。

**我一开始把这个读成"分发问题不是内容问题"，错了。** 低播放 + 正常完播率正是「减少推荐」
的形态——播放被掐、内容本身没变。断崖**就是**那次判罚生效，不是判罚之前发生的别的事。
用户纠正：问题就发生在那个时候，只是他后来才说。教训：不要把"合规事件的时间"和"我知道
它的时间"混为一谈；数据里的断点比档案里的日期更可信。

**由此修正的结论**：视频号上仍公开的 33 部旧片不是"内容还行只是没量"，而是账号仍在为之
付代价——**下架优先于重制**，是一次性止血动作，不是"先查清再说"。抖音 9 月仍有
1000–4900 播放，未受影响。

### 推送通道：HTTPS 不通，SSH 通（重要）

`https://github.com/...` 的 git push 在这台机器上**挂住不动**（`--verbose` 只打印
"Pushing to https://..." 然后 timeout，480 秒也不动），而：

| 探测 | 结果 |
|---|---|
| `curl https://github.com` | 200 |
| `curl -X POST .../git-receive-pack` | 401（可达，只是没认证） |
| `github.com:22` | 通 |
| `ssh -T git@github.com` | `Hi fantymoon!` 认证成功 |

**结论：remote 用 SSH。** 已改为 `git@github.com:fantymoon/Herbal.git`，push 一次就过。
本机已有 `~/.ssh/id_ed25519`，GitHub 上已登记。

（第一次 HTTPS 推送成功过——远端空仓库时不需要 want/have 协商。之后就有了，所以卡住。）

### 2s 跳出率：账号自己在变好，所以 8 月的相关性是假的

- 8 月 n=25：2s 跳出 **22.6%–41.1%，中位 31.6%**
- 9 月 n=24：2s 跳出 **18.2%–35.4%，中位 25.2%**

**中位从 31.6% 降到 25.2%**——标题写法在这两个月里自己变好了。这解释了为什么 8 月里
「阅读压力 vs 2s 跳出」是 +0.194（正相关，说不通）：那是发布时间在作祟，不是阅读压力。

9 月内部仍有 2 倍差距（18.2%–35.4%），但**样本太小，立不出标题规则**：

| 标题 | 2s跳出 |
|---|---|
| 女萎：就是后来的玉竹 | 18.2% |
| 防葵：博物志说它与狼毒相似 | 19.0% |
| 车前子：牛迹里长出的当道草 | 22.0% |
| 赤箭：其实就是天麻 | 22.1% |
| … | |
| 充蔚子：本经里的益母草子 | 31.5% |
| 青芝：入肝应春的明目芝 | 32.0% |
| 远志：它的叶子叫小草 | 32.8% |
| 细辛：华阴色白者为善 | 35.4% |

差的几条共同点是"给了一个对冷启动观众无意义的古书细节"，好的几条给了可感的现代锚点
（玉竹 / 天麻 / 当道草）。**但「远志：它的叶子叫小草」也具体却排倒数第三，所以这只是
方向不是规则**。按「就是/其实/后来」分桶只有 3 条命中，统计上说明不了任何事。

**结论：标题/封面这一层现在无法验证**——抖音导出里 `封面点击率` 一列是 `-`，平台没给。
在拿到那个数之前改封面是盲投。
