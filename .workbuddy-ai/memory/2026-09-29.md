## 台账文案也要过门禁（回应用户「发布文案呢」）

用户问四部新片的发布文案。读齐四份台账时发现一个**真缺口**：门禁只检查台账字段**是否存在**，
不检查字段里**写了什么**。而视频号那次处罚是落在标题/描述上的，不是落在某一帧上——也就是
说，一部画面完全合规的片，可以带着一个不合规的标题上线。

修法：`scripts/lib/ledger.ts` 加 `checkLedgerCopy`，用**与片内同一张**违禁词表扫
`标题：`/`描述：`/`话题：`，再叠一组账号定位词 `OFF_POSITION_WORDS`（`养生`、`调理`、
`健康科普`、`疗效`、`药效`、`治病`、`防病`）——这组词来自「账号已转为文化/读书向」这个
既定事实，SKILL.md 的定位段本来就写着「不出现养生、调理、健康科普字样」，只是没人执行。
接点两处：`check-films.ts` 的 `ledgerProblems`、`verify-film.mjs` 的 pre-flight。
空字段不报——`ledgerProblems` 已经报字段缺失，同一处缺口报两次没有意义。

**已验证守卫会响**：往紫芝台账标题里塞「治疗」，`npm run check` FAIL、`npm run verify`
直接停渲染；还原后干净。

## 第二条缺口：标题框架是集合性质，单部片查不出来

SKILL.md 第 141 行写着「不要在影片之间复用同一个固定的提问模板」。我核了四部新片的标题，
发现防风与决明子用的是同一个句式「X：古书说的「Y」是什么」——**我自己刚违反的规则**。
而这条规则单看任何一部片都看不出来，只有把标题当集合看才存在。

加 `titleFrame` / `checkTitleFrames`：把药名（首个「：」之前）与「」里的词视作**槽位**剥掉，
剩下的就是框架；两部片框架相同即 FAIL。跨片规则接在 `check-films.ts` 循环之后
（`verify-film.mjs` 只看得见一部片，接不上，这是对的）。同样验证过会响，会指名报出
`fangfeng-first-film.tsx / juemingzi-first-film.tsx share one title frame: "古书说的「」是什么"`。

顺手改掉两条标题：
- 紫芝：`六芝之一，色紫如桑` → `六芝之一，形如桑`。《名医》原文是「色紫，形如桑」，
  我原来那句把「形」错安到了「色」上——原文照录的项目里，这种压缩不能接受。
- 决明子：`古书说的「青盲」是什么` → `又名草决明`。避开与防风撞框架；别名是 SKILL.md
  点名的合法角度之一（问别名），而且「草决明」是大众认得的名字，有认知钩子。

## 第三条：生成器默认值还在说旧定位

`draftTags` 生成的是 `#<条目> #<书名> #本草 #中草药`。话题标签不是装饰——它决定平台把片子
推给谁，而 `#中草药` 招来的正是那次推荐降权所针对的人群。改成 `#<书名> #本草 #古籍
#传统文化 #读书`，与四部手写的话题对齐；黄芝台账里的旧值也一并改掉。理由和上面一样：
**一个与既定定位相矛盾的默认值，是留给下一部片的陷阱**。
