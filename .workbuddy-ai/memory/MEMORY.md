# MEMORY.md · 本草短视频项目

长期事实与约定。权威文档是 `AGENTS.md`（工程约定）与 `.agents/skills/herbal-short-video-production/SKILL.md`（制作规范）；这里只记它们没写、但每次工作都要知道的东西。**写完一条就压缩一条**——这份文件会被注入每一次会话，长了就会被截断，截断的部分等于不存在。

## 账号处境

- 视频号因「尚未被现代科学证实或夸大功效」被减少推荐，**生效在 2026-08-19 与 08-21 之间**
  （平台导出回填：08-19 菟丝子 1642 播放 → 08-21 起 0–29，完播率同期未变差）。申诉机会已用完，
  客服工单待发。详见 `remotion-video/upload/_incidents.md`。抖音无警告，是基本盘。
- 定位已转**文化 / 读书**向，**已机器强制**：`OFF_POSITION_WORDS`（`养生`/`调理`/`健康科普`/`疗效`/`药效`/`治病`/`防病`）
  出现在标题/描述/话题即 FAIL；话题默认 `#<书名> #本草 #古籍 #传统文化 #读书`（原 `#中草药` 招来的正是降权针对的人群）。
- **平台处罚落在文案上，不落在画面上**，所以门禁扫的不止片内文字，还包括台账的 `标题：`/`描述：`/`话题：`
  （`checkLedgerCopy`，与片内共用同一张违禁词表）。只扫画面会放出一部画面合规、标题不合规的片。
  **一个与既定定位相矛盾的生成器默认值，是留给下一部片的陷阱。**
- **判据：写新规则前先问「它会不会判一部在线片 FAIL」**——会，就得先决定这部片是否豁免。
  在线的不止冻结的 55 部：`frozen-films.ts` 是 2026-09-21 快照（老片没台账，快照是唯一办法），
  之后发布的靠 `out/` 里有没有母版认出来，`npm run check` 报成 `rendered`，与冻结片同等待遇
  ——**一部在线片撤不回来，判决没有意义**。

## 内容硬约束

- **功效句必须框定为历史认知**：`今译` 的功效句以 `古籍称其主……` 开头，`注释` 块必须含 `此为汉代认知，未经现代科学证实`。
- 被禁现代疗效动词（片内今译/注释、标题、描述、话题）：`治疗`、`主治`、`改善`、`有效`、`根治`、`特效`、`治愈`、`秘方`、`神效`、`必备`、`包治`、`断根`、`奇效`、`立竿见影`、`药到病除`。
- `今译` 是逐句现代汉语翻译，不是概括评论；评论/说明一律放 `注释` 块。
- **一个词的读法要找对「对本条作证」的那条证据，后世语料不能替本条作证。** 龙眼「安志厌食」的「厌」
  读平声、义为**饱足**：《本草经解》对**这一条**给了直接训释。我曾按「全库 79 处『厌食』都作『恶心厌食』」
  写成「不欲饮食」——那 79 处全是后世用法。**手边有一个大规模、好检索、方向一致的证据，恰恰是绕过
  那条唯一直接证据的最舒服的方式。** `--grep` 的命中数不是权威性。
- **`今译` 与 `注释` 不得给出互相矛盾的训释**（龙眼曾同时出现「安于饮食」与「指不欲饮食」）。没有门禁看这一眼，渲染前逐条核对。
- 三屏（hero / classical / closing）是既有视觉语言。`ALLOWED_DURATIONS = [360,450,540,630,720]`，
  **实际只落到 450/540/630/720（15–24 秒）**，360 已不可达（每场景至少 120 帧 × 3 屏 + 阅读预算）；
  `EXTENDED_DURATIONS = [810,900]` 只能靠声明 `duration` 偏离到达。
- **容量上限：今译×1.55 时标准档 83 字原文；声明 `duration` 后 130 字**（×1.8 → 83/112；×2.1 → 66/102）。
  古典屏同屏装原文+今译+注释+历史框定，**原文长度才是约束**。这是拿真 `planFilm` 扫出来的。
- **屏幕上的事实只有 `产地` 是凭记忆写的，所以它现在是门禁。** `别名` 从经文 `一名…` 读，`篇目位置` 从
  `<目录>` 读，`产地` 脚手架从来不派生——大枣因此在结尾屏写「池泽」而经文写「生平泽」，「池泽」是紧邻的
  藕实茎的生境。`originProblems` 要求 `产地` 是经文点名的地名，脚手架改用 `originOf(sutra)` 派生。
  **已知同病且在线、不能改的三部**：蓝实、紫芝、黄芝，在 `tests/corpus.test.ts` 里钉住，只减不增。
- **`deviations` 是「预算可谈、安全不可谈」的分界**（`src/layout.ts` 的 `NEGOTIABLE_RULES`）。安全规则
  （违禁词、历史框定、免责声明、几何、配图）**没有豁免通道**——「能渲染的必然合规」靠的就是这条。
  预算规则（`duration`/`reading-budget`/`pacing`）可凭**非空理由**豁免，豁免不删除违规、只盖 `waived` 戳，
  `npm run check` 会把影片自己的理由打印出来。**`why` 是要被核对的内容，不是注释。**

## 协作方式

- **这个工作流由大模型驱动，不要为「判断类」的事写生成器。** 标题、描述这类文案模型自己写——
  `draftTitle` 只是保证字段非空的占位，不是作者。我曾把「别等我敲定」读成「去写个更好的生成器」，
  加了一堆候选拼装逻辑，被否掉。**判据：需要品味的地方用判断，需要重复的地方才用代码。**
- **能自己产出的就别问。** 用户说过「这些应该在工作流里批量生成的东西你就别等我敲定」。
  只有决定依赖只有他知道的信息（平台后台、他的偏好）时才问。
- **门禁和生成器是两份东西，删字段要同时删两处。** `ledger.ts` 停写 `抖音：`/`视频号：` 之后，
  `check-films.ts` 的必填清单还在要它们，只因为每部片都有母版、台账检查被短路，这条错要求从未响过。
  **验证办法：把一部片的母版临时移开再跑 `--film=`**——这是唯一能让"只对新片生效"的门禁现形的办法。

## 测试与门禁的取舍

- **判据：这条测试能不能在一个真实缺陷上变红？** 不能的就不该存在。
  - **该删的**：断言源码字面量（`source.includes("trimAfter={durationInFrames}")`——它守护的正是那个
    让音床在 4:16 死掉的表达式）、断言文档措辞（曾用 60 条中文句子钉 SKILL.md，改一句就红，
    而同一份文档同时写着「第 0 帧是封面」和「第 0 帧是一张空白纸」它却看不见）、
    对已冻结影片逐片断言其自身字面量（**测一个常量**）。
  - **该留的**：喂给门禁一个坏输入、看它拒绝（`compliance.test.ts` 27 条全是这种）；
    以及覆盖**每一部**片的集合性扫描——它们连下一部片一起管。
- 2026-10-05 按这条判据从 218 条删到 151 条。
- **集合性质的不变量只有 `check-films.ts` 查得了**（它看得见全集）：`checkTitleFrames` 把药名与「」里的词
  当槽位剥掉后比标题框架，两部相同即 FAIL；`adjacentTrackRepeats` 比发布顺序相邻两部是否同曲。
  `verify-film.mjs` 只看得见一部片，接不上。**这类「集合性质的不变量」是独立的一类门禁。**
- **fixture 不要钉平台自己的数字**：`stats-import.test.ts` 曾把抖音导出行数硬编码成「49 部 + 表头」，
  平台换了导出（49→54）就把套件弄红一整天。改成结构不变式（每行要么被安置、要么被报为未安置）。

## 生产约定

- 新片是**数据不是 JSX**：`npm run new-film -- --id=<CompId> [--latin=] [--entry=]` 一次生成内容模块、影片包装、上传台账。
  默认取 `progress.json` 首个 todo（原序），`--entry=` 可跳选——**生产顺序与发布顺序是两件事**，
  SKILL.md 禁止在片内展示工作流顺序。发布顺序见根目录 `publish-plan.md`。
- 内容模块留 TODO 即为 draft：`gen` 不注册、`verify` 拒绝渲染，所以 draft 无法上线。
- 不要手写 `position: absolute` 或自选字号，全走 `src/layout.ts` 的 `TYPE`；否则门禁 FAIL。
- 已发布影片在 `scripts/lib/frozen-films.ts` 冻结，只减不增；**已发布的条目不再重做上线**，要重制必须先下架旧片。
- **两个预算都要过门禁**：几何（不重叠、不溢出、每屏 ≥120 帧）与阅读（`READING_RATE_LIMIT = 15` 字/秒）。
- **台账不要手写**：文案字段由 `ledger` 生成，数据列由 `stats` 从平台导出并进。

## 语料（`TCM-Ancient-Books-master/`）

- **语料是 GB18030，不是 UTF-8——`rg` 在整条语料线上完全失效**（701 个 txt 全部如此，会把「明明有这一条」
  报成「查无此条」）。检索一律 `npm run entry -- --grep=<词>`，核对单条 `--name=<条目名>`。
- **条目名有残缺**：`000-神农本草经.txt` 中至少 17 条 `<篇名>` 被截断（`青`→青蘘、`木`→檗木、`KT`→编码残缺）。
  开新片前核对内容行首句，把全名写进内容模块的 `entry`。
- **残缺有三类，前两类看得见，第三类看不见。`npm run entry` 只拦前两类**（350 条里 3 条截断 + 28 条掉字）：
  ① **断在连接词上**（卷柏「…轻身、和《吴普》曰」）；② **行内掉字**——底本用空格占位（龙骨「惊痫 疾狂走」、
  黄连「目痛、 伤泣出」）。**空格归一化会把缺字悄悄粘成通顺句子**，比明显空缺更危险。遇到就跳过或换底本，
  不要猜字；确要补字用 `new-film --recension=<字> --why=<据何本>`（必须同时给），补字与依据会写进注释与台账备注。
  ③ **讹字**——字写错、读起来通顺、行内没有空格，`corpus.ts` 抓不到（大枣底本「肋十二经」／证类「助十二经」）。
  **开新片前跑 `npm run variants`。**
- **`npm run variants` 是报告不是门禁**：底本与《证类本草》逐条 LCS 对读，645 处单字差异，按「只有一侧得到
  全库作证」筛出 24 处。**判据要两半**——两侧不同 × 底本那一读法全库几乎无人作证；只取一半都不行
  （「凡差异皆错」报 174 处，独特 ≠ 错）。剩下的仍有半数古今字（创/疮、利/痢、注/疰），
  **把它们也筛掉就等于把「我已经相信的东西」编进筛子**，所以分类留给眼睛。
- **语料读取统一走 `scripts/lib/corpus.ts`**（`findEntries`/`sutraOf`/`defectOf`/`originOf`/`originProblems`/`fillGaps`）。
  以前两处各写一份，`new-film` 只读 `内容：` 的**第一行**，于是所有跨行经文都被生成成截断的 `original`
  （决明子曾是「…益精光（《太平御览》」——读起来像完整句子）。新片先看 `original` 有没有断在半句。

## 配图通道

- **维基媒体 / Openverse / archive.org / pixabay / gitee 在这台机器上全部超时或 403**（走代理出网）。
  **SKILL.md 已写备用通道，照它做。** 备用：`plants.sc.egov.usda.gov`（公有领域）、`calphotos.berkeley.edu`（CC 带署名）。
- **可用通道是 iNaturalist**：`api.inaturalist.org` + `inaturalist-open-data.s3.amazonaws.com`。只取 CC0 / CC BY / CC BY-SA。
  `npm run fetch-photo` 一条命令完成查询+下载+登记。
- **三个坑**：① **扩展名因图而异**（同桶同许可都可能 `.jpg` / `.jpeg`），硬编码任一种会静默砍掉一半图库。
  ② **不是每张 CC 图都在开放数据桶里**，有些 id 404，要按候选逐个试。③ 代理偶发 `ECONNRESET`，脚本已加重试
  ——没有重试时，一次抖动会被报成「这个分类没有图」。
- **自动排序看不见内容**：横向→分辨率→许可的启发式看不出「密叶丛」比「整株带花」差，所以
  `--check` 列候选、肉眼看、`--id=` 取是正常流程；**`--id=` 查的是未过滤列表**，要 `--fruiting --id=` 一起给。
  `--fruiting` 是「画面里有没有果实」的唯一信号。插框约 1.9:1 横向裁切，**竖构图会切掉主体**。
- **`credits.json` 必须与 `public/images/` 完全一致，且每张图都要被某部成片引用**——下载与建片必须成对，不能先囤图。
- **Node 走代理**：`process.env.NODE_USE_ENV_PROXY = "1"`（Node 22 支持）。**子进程：异步 `spawn` 可用，
  同步形式（`execFileSync`/`spawnSync`）返回 EBUSY。** 用同步形式写音床检查时 ffmpeg 解码静默失败，
  表现成「这个文件没有音频」，是个会把人带偏的假象。

## 音乐通道

- **曲长是门禁的输入，不是注释。** `npm run sync-music` 复制曲目并写 `src/music-registry.ts`（曲长用纯 JS 走
  mp3 帧头数出来、开头静音、来源）。片子写的曲子不在表里，`npm run check` FAIL。**加曲目：mp3 丢进仓库根的
  `music/`（原始中文名），在 `scripts/sync-music.mjs` 的 `TRACKS` 加一条，再跑它**（它负责改 ASCII 名、量长度、量开头静音）。
- **`@remotion/media` 的 `loop` 会静默失效。** 它从 `trimAfter` 推循环长度；取不到资源时长时把媒体当无限长，
  于是「`loop` + 整片长度的 `trimAfter`」= 只播一遍。没有报错、没有警告。`FinishedMusic` 因此查注册表，
  把 `trimAfter` 设成曲子自身长度，`trimBefore` 用开头静音长度（否则每个接缝多一个空洞）。
  **判据：库的「聪明默认」在取不到输入时会退化成无操作，而退化路径不报警。改完要量，不能只看代码对不对。**
- **`ffprobe` 通过不代表音轨没问题**：它报的是流，不是采样。`verify` 与 `topic:verify` 都会解码音轨，
  断言曲子起播后没有 ≥1 秒纯零段（判据是 `-180 dBFS` 这种只有「什么都没有」才到得了的地板）。
  长视频系列此前完全没有检查，缺陷正活在那里。**六分钟母版 `out/tu-que-h.mp4` 的最后 1:46 曾是数字静音。**
- **发布顺序 ≠ 书内原序。** 按 `progress.json` 原序量轮换，14 部新片相邻同曲 8 处；按 `publish-plan.md`
  的发布顺序量，前六部完美交替。**数字没错，是序列错了。**
- **线上听到的就是母版里那一首。** BGM 混进母版音轨，平台配乐只能**叠加**不能替换（关掉原声会连口播一起关掉）。
  「上传时用平台曲库替换」是一条做不到的指令，**换曲必须重渲**。**2026-10-05 用户直接否掉了那条假定，
  连带推翻了由它推出的「扩库不影响线上观感」——扩库直接影响观感。**
- **曲库 5 首**（2026-10-05）：渔舟唱晚·古筝 4:16、高山流水 3:31、古镇旅行·中国风 2:43、箜音古涧·箜篌 1:39、风过檐角轻 1:53。
  前两首承载了全部 72 部旧片，**新片不要默认回落到它们**。每部片只用 12–30 秒，
  **素材量不缺，缺的是「不同的曲子」**——问题从来不在库容。
- **可达的音乐源只剩一家**（2026-10-05 实测）：FMA 200 但无接口（`/api/*` 全 404）；incompetech 200（CC-BY，西方合成器，
  声纹不搭）；musopen 403；**爱给网 403**（更正：此前记的「可达」是偶发）；archive.org / Commons / Openverse / Pixabay 全超时。
  **「找不到更多曲子」是可达性事实，不是没找。**
- **「再找几首 BGM」是四层里最浅的一层**：① 运营层（**不存在**，见上）② 分配层（哪部用哪首，**已解决**并有门禁）
  ③ 库容层（**已探明**）④ 身份层（固定开场/收尾音、口播，**真正的杠杆，完全没用过**）。
  **同样几首曲子配一个固定开场，辨识度提升远大于五首曲子随机分配。** 分配层与库容层的缺陷有门禁能查；
  身份层的缺陷没有任何自动化能看见——**这正是它一直没动的原因。**
