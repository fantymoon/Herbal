## 一条工具事实

**`npm run entry -- --grep=` 是字面匹配，不支持 `|`。** 单条「相招以文无」命中 3 条，写成「相招以文无|文无一名当归」就 0 条——而且它会照常打印「0 hit(s)」，看起来像"语料里没有"。**要正则只能用 `dots` 的 `search`（构建时真跑正则）。判据：grep 返回 0 时，先用单条短语验一次，别直接当成"没有"。**

## 本草一问 06 · 藕实茎（另一条线，另一个会话）

出了 `asks/oushijing.yaml` → `out/asks/oushijing.mp4`（1080x1920，44.3s，9.6MB），

**考据的路子值得复用**：这一集的答案不在《本经》经文里，而在**这一条自己的案语**里——
孙星衍辑本引《说文》「藕，夫渠根；莲，夫渠之实也；茄，夫渠茎」，三个字正好是荷的三个部位。
所以「书」屏照录的是这一句（出处写「《说文解字》（《神农本草经》藕实茎条案引）」，两头都交代）。
**判据：一条药的答案常常就在它自己的案语里，先读整条，别只读经文那一行。**

另外两处：《尔雅》给荷的每个部位都起了名（茎茄、叶蕸、本蔤、华菡萏、实莲、根藕）——
**一部《尔雅》只有荷被这样逐个部位命名**；而《证类》明写名字怎么串的
（「此皆名相错，习俗传误，失其正体也」），《纲目》里连「荷」指根、指叶还是指茎都有三人三说。

## 本轮改的代码（三处，都是被真实缺陷逼出来的）

1. **`scripts/fetch-photo.mjs` 会误杀真图。** 它用 `body.length > 100_000` 判"这是不是照片"，
   而 `669468250` 是合法的 200 响应、97 966 字节的 JPEG，被判成 "none downloaded"；
   `669468205` 以 100 384 字节勉强通过。**魔数检查本来就在做，字节数下限只是"照片都很大"的错觉——
   一个会拒绝真实输入的守卫，读起来和"这张图不存在"一模一样。** 改成 1024。
2. **`scripts/ask-verify.mjs` 渲染没带 `--bundle-cache=false`。** 长视频线刚踩过
   「`still` 用新代码、`render` 用旧 bundle」，这条线也会中，补上。
3. **`npm run entry` 加了 `--around=<n>`。** `--grep` 只给行号，而语料**行内折行**——
   一条命中常常是一段话的中间片段，主语在两行之上。这一集的考据要读六次上下文，
   每次都得现写一个临时脚本。现在 `--grep=恐即是根 --around=4` 一条命令给出。
   （临时脚本 `_corpus-range.mjs` / `_tmp-byid.mjs` / `_tmp-lotus.mjs` 已删。）

## 三个渲染教训（都写进代码注释了）

1. **`writing-mode: vertical-rl` + `text-orientation: upright` 在本机 Chromium 里没生效**，
   字被横倒 90°。改成一字一格排成一列——**一列 div 没有那个自由度，也就没有那个失败方式。**
2. **字号要除以行高**：15 字 × 字号 × 1.5 才是这一列真正占的高度。少除那个 1.5，
   字列比框高三分之一。
3. **框高给了，位置也要算**：竖版引文第一版 `top:960 + height:820 = 1780`，
   而系列名在 1762——正好压上。**给了高度不等于算过终点。**

# 用户第二轮：竖封面的排版

> 「感觉竖封面的排版不太对」

**症状**：下半幅一大片空白，引文挤在左下角、小到缩略图里看不见——**它成了装饰，不是内容**。

**根因**：我只把**点出的那一句**（13 字）竖排出来。而片子里的书页是**整页照录文排成多列**的。
封面照做才对得上，而「点出哪一句」应该靠**朱红**，不该靠「只剩一句」。

**改法**：`PageBlock` 用 `page.text` 整页排版，把 `marks[0]` 的 `[a,b)` 那段染成朱红。
字号按列算（一列装 `高/(字号×1.5)` 字，`列数×字号×1.6 ≤ 宽`，取装得下的最大字号），
所以**框给多大就排多满**——这正是封面和成片对得上、而不像贴了张图的原因。

横版 6 列、竖版 8 列，两种封面都是同一套排版，只是框不同。

## 一条可复用的判据

**封面上的元素要么承担信息，要么去掉。** 缩略图只有 200px 宽，
一个"看得见但读不了"的小竖条在那里既不是图也不是字——**它只是占据了位置**。
