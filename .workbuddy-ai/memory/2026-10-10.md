## 两条考据方法

## 已知缺口（这一线）

- **三条门禁都不核对引文与语料是否逐字一致**。底本有掉字（`corpus.ts` 报的 `□`）时，
  那个缺口会原样上屏而 `ask:check` 照常打 `ok`。开一集之前先跑
  `npm run entry -- --name=<条目>` 看有没有缺字提示。已写进 asks/README。
- **`--check` 的 ⚠ 要分两种**：观察者鉴定与搜索名**不同 taxon**（橘柚配成酸橙）是配错；
  **同一个 taxon 的异名/变种**（徐长卿 = Vincetoxicum bungei，百合 var. viridulum）不是。
  判据：查 `api.inaturalist.org/v1/taxa?q=<学名>`，返回同一个 id 就是同物异名。

## 又一个真缺陷：书屏朱红没有下界

`src/ask-film.tsx` 算出了 `quoteOffset`（read 在引文里的起点），**却只用它接时间轴**，
染色写的是 `i <= litUpTo`——没有下界，于是**朱红永远从引文的第一个字开始亮**。
旁白只读中间一句时，屏幕上从引文开头一路红到 read 结束。

败酱那一集旁白只读「疸痔」，屏幕上却从「味苦」红到「疸痔」。**9 集里 5 集受影响**
（读整段的 dazao-ye / wangbuliuxing 不受影响）。改成 `i >= redFrom && i <= litUpTo`，
`redFrom` 取"第一个 `indexMap >= quoteOffset` 的字"（标点的 indexMap 是 -1，
直接用 quoteOffset 当下标会让 read 中间的标点留在黑里、朱红断成两截）。

**这个缺陷读代码看不出来**——`quoteOffset` 就在那里，看着像用上了；README 也写着
「引文的哪个字开始亮，由 read 在引文里的位置决定」，读起来像已经实现。只有渲一张
书屏末帧、看朱红落在哪几个字上，才会露馅。**判据：旁白只读中间一句时，书屏末帧的
朱红应当只有那一句。**

**教训（今天第二次）**：`quoteOffset` / `peakVolume` / `crosses` 这一类**算出来但没接上**
的中间量，是这类 bug 的共同形态——**一个变量被计算，不等于它被使用**。
判据不是"这段代码看起来对不对"，是"渲染出来的那一帧对不对"。
