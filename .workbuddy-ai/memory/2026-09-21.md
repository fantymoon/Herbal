## 追加 · 数据化引擎落地（同日晚，commit `a4d0609`）

**做了什么**：把「一部影片 = 303 行手写 JSX」拆成三层，新片影片文件降到 5 行。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 内容数据 | `src/films/<kebab>.ts` | `FilmContent` 对象，唯一写文案的地方 |
| 布局引擎 | `src/layout.ts` | 几何、字号刻度 `TYPE`、场景拆分、时长、节奏 |
| 渲染器 | `src/entry-film.tsx` | 按 plan 分派绘制 |

配套：`scripts/new-film.ts`（`npm run new-film -- --id=... --latin=...`）从语料读原文，一次生成内容模块 + 影片文件 + 台账，把原来五处手工维护收成一处。`scripts/lib/film-content.ts` 是 gen/check/verify/tests 共用的内容加载器。

**关键设计：draft 状态**。脚手架**故意**产出带 TODO 的未完成影片，而闸门扫 `src/finished/`——不处理的话用一次脚手架就把测试搞红。解法是把"未完成"做成机器可判定状态：内容模块仍含 TODO 的数据化影片是 draft。

- `gen` 不注册 → 无 Composition → **不可渲染、不可发布**
- `verify` 直接拒绝；`check` 报 `draft` 行且退出码 0；`progress` 不计入 done
- 有一条测试断言 **draft 绝不出现在 `Composition.tsx`**
- 因为 draft 严格更弱（渲染不出来），放宽容忍度不是后门，「能渲染的必然合规」仍闭合

**静帧冒烟验证抓到的三个真实缺陷**（单测发现不了，必须渲染 + 与已发布影片同帧并排比对）：

1. **预留高度与实际行高不符**：所有块按 1.5 行高预留，hero 标题 150px 预留 225px 而实际 0.92 行高只有 138px → 整段 hero 比已发布影片低约 87px。修法：行高按角色区分（标题 0.92 / 副标题 1.15 / 古籍 1.35 / 正文 1.5 / meta 1.2），并加断言「预留高度必须跟随实际行高」。
2. **错峰出场太慢**：`6 + index*9`，第 8 块 delay=69、第 95 帧才淡入完，而场景只有 120 帧。已发布影片最晚 32 帧起步。改为 `2 + index*4`（最晚第 56 帧完成）。
3. **文字裸排装饰山水上**：hero 原文摘句落在 y≈1240 起的山峦上（低对比像灰渍），印章悬在中段。修法：原文 + 书目引文合并成带边框面板（衬底 + 3px 强调线），印章锚定画框底部（`CANVAS.height - BOTTOM_RESERVE - SIGN_SIZE`）。

**顺带修的两处规则/引擎不一致**：
- 引擎输出书目引文漏了书名号 `《》`，导致重复扫描把「书名 · 卷次」判成内容重复——豁免规则要求 `text.includes("《")`。已在 `layout.ts` 加 `citation()` 统一构造。
- 已发布影片顶部标签是书名罗马字（`SHENNONG BENCAO JING`），引擎却渲染中文书名。给 `FilmContent` 加 `bookLatin`，书配置 `scripts/books/*.mjs` 加同名字段。

**其他修复**：`verify-film.mjs` 原来从影片文件正则抓 `durationInFrames={...}` 和 `breaks={[a,b]}`，数据化影片没有这些字面量，且 4 场景时 breaks 是 3 个——改为从 `planFilm` 取，静帧采样点也改成「首场 / 最后一个古籍场 / 收尾场」；`tests/finished-video.test.ts` 的全量扫描新增 `renderableFiles`（排除 draft），并把数据化影片的配图作者/授权改为与 `credits.json` **逐字段相等**比对。
