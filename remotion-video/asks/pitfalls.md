# 本草一问 · 踩坑与判据

`README.md` 讲**怎么做对**。这份讲**为什么是现在这样**：每个阈值、每条规则都从一次具体的错里长出来。
改规则之前先读对应那一条，否则会把一个已知缺陷重新装回去。

## 断行：自动折行的断点落在第 9–10 个字，不是词与词之间

封面大字是 92px，容器 936px，所以**一行只放得下 9–10 个字**。中文在任意两字之间都能
折行，于是容器自动折的时候，断点一定落在第 9–10 个字上——**不管那里是不是词中间**。
实测折出来过「为什／么」「连／在一起」。

判据是看一眼封面，因为这件事只有眼睛看得出来：`npx remotion still Ask<Id> out/asks/stills/qc.png
--frame=0 --bundle-cache=false`。

## 配图的三道坎

**一、`--check` 的排序看不见内容。** 列表按「横构图 → 分辨率 → 许可」排——它答的是
「哪张技术上更好」，不是「哪张是你要的部位」。排在前面的常常是一整片荷塘。

**二、`--id=` 只能从 `--check` 的列表里选。** 两条合起来决定了那个工作流：不能跳过列表
直接猜 id，也不能把「排第一」当成「选好了」。**下载与建片必须成对，不能先囤图。**

**三、取图脚本曾有一条会误杀真图的守卫。** 它用 `body.length > 100_000` 判断"这是不是一张照片"。
`669468250` 是合法的 200 响应、97 966 字节的 JPEG，被它判成 "none downloaded"；
`669468205` 以 100 384 字节勉强通过。魔数检查本来就在做，字节数下限只是"照片都很大"的错觉，
而**一个会拒绝真实输入的守卫，读起来和"这张图不存在"一模一样**。已改成 1024。

另外 `--check` 的 ⚠ 不总是配错：iNaturalist 的同物异名会让两个学名落到同一个 taxon
（徐长卿的 `Cynanchum paniculatum` 与 `Vincetoxicum pycnostelma` 都是 1638659）。遇到 ⚠ 先查
`api.inaturalist.org/v1/taxa?q=<学名>` 返回的 id 是不是同一个，再决定是不是假警报。

## 「书」屏的朱红曾经永远从引文第一个字开始亮

渲染器里算出了 `quoteOffset`（read 在引文里的起点），却只用它接时间轴，染色写的是
`i <= litUpTo`——**没有下界**，于是朱红永远从引文的第一个字开始亮。败酱那一集，旁白只读
「疸痔」，屏幕上却从「味苦」一路红到「疸痔」。现在起点也换算成字符下标（`redFrom`），
染色是 `i >= redFrom && i <= litUpTo`。

**这个缺陷靠读代码看不出来**（`quoteOffset` 就在那儿，看着像用上了），只有看图才露馅。
判据：旁白只读中间一句时，渲一张书屏末帧，朱红应当只有那一句。

## 三条门禁不查引文与语料是否一致

单味药线有 `quoteProblems` 和 `defectOf` 把这条钉住，这一线没有——规则一只看功效词，
规则二只看出处非空。后果很具体：底本有**掉字**（`corpus.ts` 报的 `□`）时，那个缺口会原样
排进竖排原文上屏，而 `ask:check` 会照常打 `ok`。所以开集前要先跑一次 `npm run entry -- --name=<条目>`，
见 README 的「开集之前必须先查的三件事」。

同一个判据也管异文：底本与《证类》不一致时，先看有没有第二个抄本支持底本——那个小的数字
不是噪音，要看那 N 处是谁。百合是 1 : 5，而那「1 处」正是《名医别录》抄的《本经》原文，
两处对一处，再看到清代还在用「张」，才能判成古今字。

## 为什么中间要编译一次

Remotion 的组件必须是纯函数，不能运行时读文件。YAML 是给人写的，TS 是给渲染器读的——
这和跨书专题系列把旁白时长编译成 `src/topics/<id>.voice.ts` 是同一条约定。

## 为什么时长在构建期算、不用 `calculateMetadata`

旁白必须先合成出来，时长才存在，而 `calculateMetadata` 跑在渲染时、合成不了音频。
结果一样（时长由旁白决定），而且渲染时不需要网络。

## 句级边界不够，必须显式要词级

`edge-tts --write-subtitles` 给的是**句级** SRT——一段 8 个字的古文只会回一条整句边界，
一个字都落不下来。所以 `scripts/tts_words.py` 直接消费 WordBoundary 事件流：

```python
edge_tts.Communicate(text, voice, proxy=PROXY, boundary="WordBoundary")
```

`boundary` 默认是 `"SentenceBoundary"`（7.x 起改的），**必须显式要词级**。

`ask-voice.ts` 再把边界摊平成 `charTimes`（第 i 个汉字在何时被读出）和 `quoteTimes`
（引文每个字的读出时刻）。「书」屏的逐字朱红靠的就是后者。

**对齐靠一条不变式**：边界里的 `text` 是归一化后的文本，把它们首尾相接，正好等于旁白
去标点后的字序列。对不上就报错——一屏朱红推进错了位，比不亮更难发现。

## 引文的 `read` 必须同时是旁白与引文的连续子串

「书」屏摆的是整段原文，旁白可以只读其中一句。引文的哪个字开始亮，由 `read` 在引文里的
位置决定，所以 `read` 必须**同时**是旁白与引文的连续子串——`ask:build` 两头都核
（少核一半，朱红就会从引文的第一个字开始亮、亮到 read 用完为止，整体错位）。
`dazao-ye` 与 `wangbuliuxing` 读的是整段（偏移 0），`juyou` 读末尾四个字、
`tianxiong` 读中间三个字——两种情形都在生产里跑过。
