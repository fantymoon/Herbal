# 本草短视频制作

本流程用于制作单味药或方剂的 9:16 竖屏科普短视频。依据给定的古籍内容新建一支成片；共用模板保持不动。

## 输入与模式

先收齐：准确的原文条目、视觉参考、可选的透明印章素材、配乐文件、目标 Composition ID。用 `npm run entry -- --grep=<词>` 检索古籍文本——**语料是 GB18030，`rg` 匹配不到任何中文，会用"查无此条"骗过你**；核对某条则用 `--name=<条目名>`，它会同时报出容量档位和两种**不能照录**的残缺：经文断在连接词上（截断），以及底本掉字（行内空格即证据，如 `惊痫 疾狂走`）。这两种都换底本核对或跳过，**不要猜字**——`原文照录` 没有改字的余地。原文照录，不得把历史描述改写成医疗建议。

一批内容涉及多本古籍时，选定一本，把该书选中的条目全部做完，再换下一本。同一批次的片名、卷次在上传文案里保持一致。

跨多支影片延续一本书时，按**原序**取下一个未覆盖的条目。除非用户明确改变顺序，不要在条目之间挑顺手的。覆盖情况记录在 `progress.json`（在 `remotion-video/` 下用 `npm run progress` 重建）；下一支就是第一个 `todo` 条目。

**原序是内部生产规则**，不是给观众看的文案。**不要在片内展示工作流顺序**：不要出现 `阅读顺序`、`按原文顺序阅读`、`ENTRY 04/05` 或批次序号之类的标注。需要出处标记时，只展示古籍真实的著录位置，例如 `卷、篇、部、章节`（如 `《神农本草经》卷二·中经`）。

定版式之前先选模式：

| 模式 | 用于 | 右上角印章 |
| --- | --- | --- |
| `single-herb` | 单味药条目 | `药` |
| `formula` | 多味组成的方剂 | `方` |

印章是一个大字，永远不是药名或方名。字号比例用 `0.5` 到 `0.6` 左右；两个字会让印章有一半是空的。

## 视觉规则

- 从参考图借用配色、纸感、取景和字体节奏。不要把参考图直接当视频背景。
- 不使用代码绘制药材、根、叶或药物主体。**配图是必需的，不是可选的**：门禁要求 `photo` 的 file/subject/license 都不是占位符，且文件已登记在 `public/images/credits.json`——**没有「无配图」这个合法状态**。所以「找不到图」的正确处置是**换一个条目**，不是省略配图。（芎藭与蘼芜就是这样被搁置的：川芎在这台机器上取不到鉴定正确的开放授权照片，GBIF 名下 139 条带图记录的鉴定名全是藁本。）本地图片放进 `public/images`，文件名用 ASCII。用 Remotion 的 `Img` 和 `staticFile` 渲染，不要用原生 `img` 或 CSS 背景图。
- 图源通道：先试 Wikimedia Commons —— 用它的 REST API（`commons.wikimedia.org/w/rest.php/v1/file/File:<name>`）取文件信息，读 JSON 里的 `original.url` 直接下载。Wikimedia 对突发请求会返回 HTTP 429 限流（每个 IP 常常持续数分钟），所以请求之间要留间隔，并备好其他通道。退路是 Openverse（`api.openverse.org/v1/images/?q=<name>&license_type=commercial`），它聚合了 Flickr、Europeana（含 naturalis.nl）、史密森学会等 CC 授权图库。**动手前先探测可达性。** 在某些网络下——中国大陆代理是常见情形——Wikimedia 和 Openverse 都超时，而 iNaturalist 通：`api.inaturalist.org/v1/observations?taxon_name=<属名>&photo_license=cc0,cc-by,cc-by-sa&quality_grade=research` 直接返回 `photos[].license_code` 和 `attribution`，同一个照片 id 在 `inaturalist-open-data.s3.amazonaws.com` 上有 `square` / `large` / `original` 三档。**扩展名不固定**：有的 id 是 `large.jpg`，有的是 `large.jpeg`，同桶、同许可都可能不同，所以要从 API 返回的 `photo.url` 读扩展名，不要硬编码——硬编码任一种都会静默砍掉一半图库，让整个分类看上去「没有可下载的图」。把它当一等通道，而不是最后手段。只接受 CC0 / CC BY / CC BY-SA 图片；把确切的文件、作者、许可记下来用于片中署名，并登记到 `public/images/credits.json`（由测试强制）。注意：署名台账必须与 `public/images` 下的文件完全一致，所以图片要先落盘再登记。以上整段由 `npm run fetch-photo -- --taxon="<学名>" --file=<文件名主干>` 一条命令完成；`--check` 先列候选，看过之后用 `--id=<photoId>` 取选定的那张（自动排序只是启发式，看不出「密叶丛」比「整株带花」差）。插框是约 1.9:1 的横向裁切，**竖构图会切掉主体**，优先挑横向图。
- 用带框的插入图，不要满幅出血。围绕真实主体裁切，必要时附一行紧凑的作者/来源/许可。
- 提供的透明印章只有在确认边缘和底色干净之后才能用。它应当是一枚含蓄的品牌标记，不是一块贴上去的不透明白方块。

```tsx
// 渲染器里的形态（`src/entry-film.tsx`），供参照——影片文件本身不要写这些：
// 印章字形来自 `sealGlyph(mode)`（单味药「药」/ 方剂「方」），由渲染器决定，
// 内容模块只声明 `mode`。`position` / 字号同样全部由 `src/layout.ts` 给出。
<Img src={staticFile(`images/${content.photo.file}`)} style={{ objectFit: "cover", objectPosition: "50% 50%" }} />
<Seal text={sealGlyph(mode)} size={104} glyphScale={0.55} rotation={-5} />
```

## 新片如何构成

新片是**数据，不是 JSX**。三个文件，只有一个装正文：

| 文件 | 装什么 |
| --- | --- |
| `src/films/<kebab>.ts` | `FilmContent` 对象——唯一写正文的地方 |
| `src/finished/<kebab>.tsx` | 约 5 行的包装：`<EntryFilm content={content} />` |
| `upload/<kebab>.md` | 上传台账（平台文案，写好后填） |

`npm run new-film -- --id=<CompositionId> [--latin=...] [--entry=...]` 一次生成这三个文件，直接从语料里读出条目的原文，其余标为 `TODO`。不要手改包装文件：几何、字号体系、场景切分、时长与节奏全部来自 `src/layout.ts`，由 `tests/layout.test.ts` 覆盖。

- **草稿态。** 内容模块里还有 `TODO` 占位符时，这支片就是*草稿*：`npm run check` 会报出来，`npm run gen` 不注册它，`npm run verify` 拒绝渲染它。所以草稿没有 Composition，到不了平台——这正是门禁报告草稿却不算失败的安全前提。清空所有占位符，片子才可渲染。
- **永远不要手写块的位置或自选字号。** 片文件里带 `position: "absolute"` 就会 FAIL，每一个字号都必须来自 `src/layout.ts` 的 `TYPE`。55 部已发布影片漂移出了 46 种不同字号、每部 11–14 个手摆的块，这正是要替换掉的维护负担。
- 文本高度按每个块自己的行高预留，所以块预留的空间永远不超过它渲染出来的。`tests/layout.test.ts` 断言这一点——曾经用 1.5 倍行框去量 150px 的主标题，把整个首屏往下推了约 87px，偏离了已发布影片的位置。
- 出场是前置的：块在 120 帧场景的约第 56 帧就全部出现完毕，与已发布影片一致。

## 移动优先的版式

- 按 `1080×1920` 构图。导出前以手机尺寸检查帧。
- 按阅读节奏，不按划过的速度：每场景至少 4 秒，总长 15、18、21 或 24 秒（30 fps 下即 450 / 540 / 630 / 720 帧）。360 帧仍在接受集合内但已不可达：它只给古典场景留 120 帧，而那一屏要装原文、`今译`、`注释` 和历史框定。`tests/compliance.test.ts` 强制时长集合、每场景下限，以及 `breaks` 的数量比场景数少一。宁可选更长时长，不要缩字号。27 / 30 秒（810 / 900 帧）只有声明 `duration` 偏离才可达，见下面「声明偏离」。入场动画要轻（约一秒的淡入/上浮）。
- **阅读预算是门禁，但它可以凭理由豁免。** 超了先试「拆到另一屏」或「缩短文本」；如果那些会把这条内容写坏，就写 `deviations: [{ rule: "reading-budget", why: "……" }]`，`npm run check` 会把你的理由打印出来。**它是预算规则，不是安全规则——写清楚理由就够了，不要为了过门禁而改坏文案。**（2026-10-02：我在络石一片上砍掉 25 字注释来迁就它，那是错的做法。） `src/layout.ts` 里的 `READING_RATE_LIMIT` 是每秒 15 个汉字——一个略读上限，约为舒适阅读速度的三倍。`npm run check` 会让最忙的一屏超出上限的影片 FAIL，*即使没有任何重叠、没有任何溢出*：几何和阅读时间是两个独立预算，55 部已发布影片的中段屏以约每秒 31 字上线，就是因为当时只检查了第一个。超载要靠缩短文本、或让切分把它摊到另一屏来解决——永远不要靠让观众读得更快。`npm run check -- --verbose` 会打印每屏的速率。
- 几何不变量是机器检查的，不靠肉眼：`src/layout.ts` 给每个块之间留至少 50px 垂直净空，`npm run check` 会让计划里存在重叠、越过底部保留区溢出、或某场景短于 4 秒的影片 FAIL。静帧仍然要你自己看——检查器判断不了照片里是不是对的物种。
- **默认用短形态：`reading: "copy"`。** 三条片场、12 秒，屏幕上只留「原文 + 出处 + 历史框定」，**今译与注释进视频描述**。理由是平台自己的数字：24 秒的片子观众平均只看 7.2 秒，12 秒的看 7.3 秒——**后 17 秒没人看，而密集文字屏正是没人看的那部分**。今译不是被删掉，是搬到能被读完的地方：没人会在一屏 145 字停留的那 6 秒里读完它，而想读译文的人在描述里可以慢慢读。`reading` 缺省仍是 `"screen"`（旧形态），所以已经渲染过的母版不会因为这条而变样。原文一屏会**放大到约 1.6 倍**并在标点处断行（`clauseLines`）——浏览器在中文里每个字之间都能断，会把「破症结积聚」拆成「破症结积／聚」，那比留白更难看。
- **渲染过的片子不动，样式改动只对新片生效。** 母版一旦落到 `out/`，它就是观众看到的那一份——不回填、不重渲。**判据：一次改动如果只能靠重渲旧片才看得见，那它就不该做。**（2026-10-05 我把封面改动重渲回 12 部旧片，那是错的。）`npm run check` 因此把 `out/` 里有母版的片子报成 `rendered`——只报告、不判 FAIL，与 55 部冻结片同等对待。唯一例外是**真缺陷**：违规数默认打印，不用加 `--verbose`。
- **台账不记录发布状态。** `抖音：`/`视频号：` 两个字段已删除。理由：一周发好几部，没人会回来更新它，字段只会烂在那儿（永远写着「未发布」），而门禁却要信一个没人维护的记录。**「这个母版能不能动」的判据是磁盘上有没有它，不是谁记得填了什么。**
- **渲染过的片子不动，样式改动只对新片生效。** 母版一旦落到 `out/`，它就是观众看到的那一份——不回填、不重渲。**判据：一次改动如果只能靠重渲旧片才看得见，那它就不该做。**（2026-10-05 我把封面改动重渲回 12 部旧片，那是错的。）`npm run check` 因此把 `out/` 里有母版的片子报成 `rendered`——只报告、不判 FAIL，与 55 部冻结片同等对待。唯一例外是**真缺陷**：违规数默认打印，不用加 `--verbose`。
- **台账不记录发布状态。** `抖音：`/`视频号：` 两个字段已删除。理由：一周发好几部，没人会回来更新它，字段只会烂在那儿（永远写着「未发布」），而门禁却要信一个没人维护的记录。**「这个母版能不能动」的判据是磁盘上有没有它，不是谁记得填了什么。**
- **第 0 帧是封面：药名满宽 + 实物照片。** 封面缩略图只有画布四分之一宽，钩子那行 56px 到缩略图上只剩约 14px——**缩略图上只有药名认得出**，所以名字必须在，而且按自己的字数取尺寸（`HERO_TITLE_LADDER`，三个字以内到顶 260px），第 0 帧再放大到满宽（`coverScale`，上限 1.8 倍），26 帧内收拢到版式位置。**但只有名字的封面是一张米色纸加两个字**——认得出，不吸引人，而缩略图是靠图被点开的。所以 `COVER_BLOCKS` 里的三块（书名标签、药名、**照片**）第 0 帧就在，其余照常淡入。**判据是「缩略图里认得出这味药，而且有图可看」，不是画面好看。**
- **第 0 帧是封面，药名要满宽。** 抖音在信息流里把封面当静帧读，缩略图大约只有画布的四分之一宽——150px 的字到手机上只剩 35px 左右，认不出是什么药，而受众以中老年为主。所以药名按自己的字数取尺寸（`HERO_TITLE_LADDER`，三个字以内到顶 260px），并且**第 0 帧再放大到满宽**（`coverScale`，上限 1.8 倍），一秒内收拢到版式位置（26 帧）。名字本身已经满宽时不再放大。**封面的判据是「缩略图里认得出这味药」**，不是画面好看。
- **首屏要带钩子，而且第 0 帧就得有东西。** 首屏原本是一张资料卡——书名、药名、拼音、部类、照片、味甘平——每一项都在向"已经在意这味药的人"描述它，没有一项能让不认识它的人留下来。钩子原本只写在平台文案里，可平台的 **2s 跳出率是量视频的**，不是量标题的。所以：内容模块写一个 `hook`（一行，`TYPE.hook` 56px，带左侧色条，位置在部类与照片之间），写**标题尾巴的屏幕版**——两者说同一句话，观众无论先读到哪个都收到同一个承诺。**钩子不得复用经文里的短语**（见「内容重复」），也不得占用片尾事实已经说过的东西。另外第 0 帧不再从空白起步：首屏的前两个块（书名标签与药名）在影片开始时就已完全显现，因为平台拿第 0 帧当封面——之前的时刻表从第 2 帧才开始淡入，封面因此是一张白纸。后续场景仍然从空白淡入，这是让换场读起来像换场的原因。时刻表在 `src/layout.ts` 的 `REVEAL_DELAYS` / `revealDelay`。
- 标题要保持主导。两条下限由测试强制、不可谈判：`今译` 正文至少 56px，任何渲染中文的元素至少 24px。纯 ASCII 的照片署名不受 24px 下限约束。次级中文目标 34px 以上，拼音/英文标签 24px 以上。照片署名要短、要次要。
- 不要靠缩小今译来解决一屏装不下。原文允许大，但 `今译`——让条目变得可读的那部分——永远不能比古典正文更小。素材装不下时，版式会把今译切分到最多三个古典场景；如果仍然溢出，那是内容问题，`npm run check` 会报出来，而不是藏在更小的字号后面。
- 用有意义的材料填满竖向叙事：身份、一句短引文、照片或事实条、原文的延续、以及结尾的出处说明。留白从容是好的；空掉中间三分之一不是。
- 不要嵌套卡片。用几道纸线、带框插入和对齐的条带，而不是一堆互不相干的浮框。
- 把长的原文引文、别名、生境和著录细节放到后面的场景，既避免字号过小，也避免空屏。
- 落在装饰性山水上的文字需要自己的衬底。首屏的原文摘录和它的出处共用一个带框面板，正是这个原因；一行裸字压在山丘上会读成一道灰印。
- 品牌标记锚定在结尾帧的底部，而不是叠在免责声明之后，这样它不会浮在空掉的下半屏中间。

## 声明偏离（`deviations`）

门禁做两件不同的事，它们不该按同一套规则谈判。

- **安全规则永不谈判**：违禁疗效动词、未框定的 `主……`、缺失的历史框定句、缺失的免责声明、文字出画、未登记的照片、非法的 `mode`。没有任何理由能让它们变得可以接受——「能渲染的必然合规」这条性质就是它们撑起来的。
- **预算规则可以偏离，但必须留痕**：影片比本系列的标准更长或更密。这是对**这一条**经文的判断，不是合规判断——语料里确有 `今译` 读不进 24 秒的条目，拒绝做它们不是安全问题，是排期问题。

做法是在内容模块里加 `deviations`，每条给出规则名和理由：

```ts
deviations: [{ rule: "duration", why: "经文 91 字，今译 259 字，24 秒读不完；本片放到 27 秒" }],
```

- 只能点名 `NEGOTIABLE_RULES`（`src/layout.ts`）：`duration` / `reading-budget` / `pacing`。点了别的规则（比如 `banned-wording`）会被判 `deviation` 并 **FAIL**，不是忽略——闸门会告诉你哪些才是可谈判的。
- `why` 不能为空。空理由 **FAIL**：一条不留痕的豁免比没有这个字段更糟。
- **豁免不会删掉违规，只会给它盖个戳。** `npm run check` 会打印 `waived [rule] … reason: <你的理由>`，影片照常渲染。留下痕迹是这套机制存在的理由。
- `duration` 是**许可**而非违规：声明之后，时长阶梯才从 720 帧放宽到 810 / 900（27 / 30 秒）。不声明时 `requiredDuration` 根本不会走到那些档位，只会在 720 封顶并让阅读预算 FAIL。
- 不要用它来回避写作问题。先试着缩短今译或让切分多摊一屏；只有当这一条经文的**忠实翻译**确实读不完，才声明偏离，并在 `why` 里写清是哪个数。

## 内容重复

- 写之前先做事实映射：把每一条来源事实、别名、生境短语和短引文分配到**只出现在一屏**。
- 不要把药名/方名、别名、生境或短的原句在首屏、原文屏、结尾屏和上传文案之间重复，除非必要的出处署名或免责声明需要。
- 用**更长的一段连续原文**或此前未用的支撑细节来填满原文屏。不要为了填地方而回收首屏那句话。
- 直接引文要保持忠实，但为了节奏可以把长条目切成互不重叠的独立摘录。
- 渲染前跑 `npm run check`，它会自动对所有可见屏幕文字做**重复字符串扫描**。它读的是影片渲染出来的文本——数据驱动的影片读内容模块和它的排版计划，冻结的手写影片读 JSX——而不是一份手写的清单，所以你没声明到的短语照样会被抓到。署名和必需的免责声明是仅有的常规例外；著录性引用（`《…》…卷/篇/部`）允许重复，这也是引用要打印成 `《书名》· 卷 · 篇` 而不是裸拼接的原因。

## 原文与今译

- 先给忠实的原文摘录，再在同一屏或下一屏给一块**明显分开的现代白话翻译**。
- **今译不是注释。** `今译` 块必须是**逐句现代汉语翻译**：跟着屏上显示的原文逐句走，保留主语、动作、宾语、限定语和不确定性，把得出的白话意思放到屏幕上。不要因为某些句子古奥就略过。
- 不得以“这段主要谈及……”等概括、评论或释义替代今译。原文说了什么，就先翻成现代汉语；无法确定的字词应在今译中保留不确定性，例如“此处字义待考”或“底本注作……”。
- 每部片必须有一个单独成块、明确标注的 `注释` / `说明` / `COMMENTARY`，放在 `今译` 之外。用它承载历史背景、版本异文、术语说明和安全框定。评论/说明可以解释背景，但绝不能顶替翻译。这个块是必需的，不是可选的：`tests/compliance.test.ts` 会让省略它、或省略下面那行历史框定的影片 FAIL。
- **把功效框定为历史认知，而不是建议。** 原文用 `主……` 表述功效时，对应的 `今译` 分句必须以历史框定 `古籍称其主……` 开头。`主` 忠实于原文；框定把它标记为历史上的认知。
- **`注释` 块必须带一行历史框定句，措辞由你定。** 闸门检查的是它做了三件事，不是它等于哪串字（`hasHistoricalFrame`，`src/layout.ts`）：①点名一个时代或古籍出处（汉代 / 古籍 / 历代 / 旧说 / 本草经……）；②否认现代知识已经证实它——否定词要在同一小句内够到「证实/验证/证明/确证/确认」，`未经现代科学证实` 过，`未经删改，现代科学证实` 不过；③点明一个现代知识领域（现代 / 科学 / 医学 / 实验 / 临床 / 药理）——单写「未经证实」不够，平台投诉针对的正是现代科学口径的功效主张，这句话要正面回应它。`此为汉代认知，未经现代科学证实` 是示例，不是唯一答案。
- 现代疗效动词——`治疗`、`主治`、`改善`、`有效`、`根治`、`特效`、`治愈`——除了直接引用原文，不得出现在 `今译` 或 `注释` 里。
- 每一处今译都要与医疗建议保持距离：不要把文本变成诊断、治疗指令、现代功效声明、剂量或安全性结论。
- **底本残缺有三类，前两类看得见，第三类看不见。** `npm run entry` 会拦下**截断**（经文断在连接词上）与**掉字**（行内空格即证据）；这两类在屏幕上会露出破绽，所以照录本身就是错的。第三类是**讹字**——字写错了：大枣底本作「肋十二经」，证类本草作「助十二经」，「肋」在这句里没有意义，可它读起来是通顺的汉语，行内没有空格，`corpus.ts` 抓不到。**开新片前跑 `npm run variants`**：它把底本与《证类本草》逐条对读，列出只有一侧得到全库作证的单字差异（434 处差异里有 24 处命中，其余的异体字、古今字要你自己判读）。它是报告不是门禁——判「讹字」还是「古今字」是对词的判断，不该由字符串做。
- **采用他本读法，就必须在 `注释` 里说出来。** 大枣的注释写「底本作「肋十二经」，《证类本草》作「助十二经」，形近而讹，今从证类」——版本异文正是 `注释` 该承载的东西。今译按采用后的读法逐句翻译。反过来，若你保留底本读法，就照它写、照它译：**原文照录没有改字的余地**，改字而不留痕比照录一个可疑的字更糟。
- **屏幕上的事实要么出自经文，要么别放。** 结尾「本草初识」的事实条是屏幕上唯一没有规则看管的散文，也是唯一凭记忆写的：`别名` 从经文的 `一名…` 句读出来，`篇目位置` 从 `<目录>` 读出来，`产地` 却曾经什么都不是——大枣因此写成了「池泽」，而经文写的是「生平泽」，「池泽」是紧邻的藕实茎的生境。**`产地` 必须是经文点名的地名**（`npm run check` 现在会判 FAIL）；经文本身不记生境的那 72 条（黄芝等）可以由别录补，但不要在引用《神农本草经》的那一屏上把别录的地方说成本经的。
- **一个词的读法，要找对本条作证的那条证据。** 后世语料不能替本条作证：龙眼「安志厌食」的「厌」读平声、义为饱足，《本草经解》附余·考证对**这一条**给了直接训释（「厌平声。饱也。纲目称其开胃益脾。补虚长智。即安志厌食之谓也」）。我曾按「全库 79 处『厌食』都作『恶心厌食』」把它写成「不欲饮食」——那 79 处全是后世本草与医案的用法，证明的是这个词后来怎么用，不是《神农本草经》这一行里它读什么。**手边有一个大规模、好检索、方向一致的证据，恰恰是绕过那条唯一直接证据的最舒服的方式。** 训释落字前先问：这条证据说的是本条，还是别处？`npm run entry -- --grep=<词>` 能搜全库，但搜到的命中数不是权威性。
- 渲染前做分句核对：每一句可见原文都要有对应的现代分句；确认没有哪句 `今译` 是以概括或评价开头，而不是在翻译。同时核对 `今译` 与 `注释` **没有给出互相矛盾的训释**——两处对同一个词各说一套，比任一处写错都更难被读者发现，而且没有任何门禁会替你看这一眼。

## 模板与音频边界

- 只新建或修改成片本身和它专门的测试。成片可以依赖的共用层是 `src/entry-film.tsx`（`EntryFilm`）、`src/layout.ts`（几何与字号体系）、`src/finished-shell.tsx`（`FinishedFilm`、`FinishedMusic`）、`src/herbal-stage.tsx`（`SceneShell`、`Seal`、配色）和 `src/herbal-cards.tsx`（`fade`、`rise`）。这一层只能向后兼容地扩展——新增可选 prop 可以，改动默认值不行，因为 55 部已发布影片都渲染在它上面。动过共用层之后，渲染一部冻结影片的静帧，确认它与改动前的静帧逐字节一致，再提交。
- `HerbalFeature`、`HerbProfileTemplate` 和 `FormulaShortTemplate` 是遗留脚手架：没有成片引用它们，代码绘制的插图（`RootIllustration`）是被禁止的。不要把她们当作新片的起点。
- 新片通过 `EntryFilm` 渲染，这也是门禁检查的。`FinishedFilm` 接受任意数量的场景，只要 `breaks.length === scenes.length - 1`，而计划会同时给出两者，所以数据驱动的影片从不自己写 `durationInFrames` 或 `breaks` 字面量。
- 用 `npm run gen` 注册影片，不要手改 `src/Composition.tsx`。`gen` 从计划里读时长，并跳过草稿。
- 配乐放在 `public/music` 下；在内容模块里写成 `music/<file>.mp3`。曲目必须先过 `npm run sync-music` 登记进 `src/music-registry.ts`——`npm run check` 会拦下没登记的。外壳通过 `FinishedMusic` 播放，低音量、轻柔淡入淡出。
- **片长超过曲子时，`loop` 不会自己生效。** `@remotion/media` 的 `loop` 从 `trimAfter` 推循环长度，取不到资源时长时会把媒体当无限长，于是「传整片长度」会让 `loop` 静默退化成「只播一遍」——没有报错、没有警告，只是音床在曲子放完处停了。所以 `FinishedMusic` 会查注册表，把 `trimAfter` 设成曲子自身长度（`trimBefore` 设成曲子开头的静音长度，免得每个接缝出现一个空洞）。这条路径只有长视频系列走得到；短片比任何曲子都短。
- **`ffprobe` 通过不代表音轨没问题。** 六分钟的 `out/tu-que-h.mp4` 配 4:16 的曲子，ffprobe 报的是健康的 AAC 流，缺陷在采样里——最后 1:46 的句子间隙是**数字静音**（-180 dBFS）。所以 `verify` 和 `topic:verify` 都会解码音轨，断言曲子起播之后不存在 ≥1 秒的纯零段。`topic:verify -- --verbose` 会打印静音发生的时刻。
- 免责声明 `古籍内容展示，不构成诊疗建议` 按构造属于结尾场景，丢掉它的计划会被门禁判 FAIL。只要历史文献描述了药用，它就必须出现——对这个语料来说，是永远。
- 下面这段是**冻结的手写形态**——它就是 55 部已发布影片的样子，也是退役影片重制时的起点，不是新片的模板。新片不得照抄。

```tsx
export const XFirstFilm: React.FC = () => (
  <FinishedFilm
    accent={accent}
    durationInFrames={360}
    music={staticFile("music/yuzhou-changwan.mp3")}
    breaks={[120, 240]}
    scenes={[HeroScene, ClassicalScene, ClosingScene]}
  />
);
```

## 平台发布

在视觉与媒体检查全部通过之后准备上传文案。用户没有指定平台时，用短视频安全默认值，不要凭空发明平台特有的限制。

- **短标题**：以药名或方名开头，接一个以出处为本的问题或事实。**与首屏 `hook` 说同一句话**——标题是屏幕钩子的平台版，两者不该各说一套。默认控制在 18 个汉字以内。避免标题党、疗效承诺或绝对化措辞。不要在影片之间复用同一个固定的提问模板（例如“古书里写了什么？”）：随条目变化措辞——问药名、问别名、问它的主句、问它在书里的位置，都可以。这条由 `checkTitleFrames` 跨片强制（见下「上传台账」）——每个标题单看都合格，撞车只在集合上看得见。
- **视频描述**：描述这条视频实际展示了什么，而不是套通用公式：点明出处条目、场景流（身份、原文、今译、结尾事实）以及出现的照片，然后是免责声明。二到四行短句。只在平台支持话题时加三到五个中性话题。
- **医疗表述**：不夸大疗效，不把古籍描述改写成“治疗”“改善”“必备”“有效”等承诺，也不补充未在素材中出现的现代医学结论。以下词语不得出现在片内今译/注释、标题、描述、话题中的任何位置（直接引用古籍原文除外）：`治疗`、`主治`、`改善`、`有效`、`根治`、`特效`、`治愈`、`秘方`、`神效`、`必备`、`包治`、`断根`、`奇效`、`立竿见影`、`药到病除`。该表由测试强制执行（2026年9月前的存量影片`主治`表述除外，见测试内名单）。
- **来源标注**：视频描述首行必须为出处，格式如`《神农本草经》卷一·上经载……`；照片署名保留作者/来源/许可（见 `public/images/credits.json`）。
- **账号定位**：账号分类选文化/读书；简介如“每日读一段本草古籍”，不出现养生、调理、健康科普字样，不承诺任何功效。这条现在由门禁强制：`OFF_POSITION_WORDS`（`养生`、`调理`、`健康科普`、`疗效`、`药效`、`治病`、`防病`）出现在标题/描述/话题里都会让 `npm run check` FAIL。话题标签的默认值也随之改为 `#<书名> #本草 #古籍 #传统文化 #读书`。
- **署名**：必需的片内照片署名要保留。只有在来源许可或平台要求时，才在描述里重复它。
- **上传台账**：每支新片都需要 `upload/<kebab>.md`，声明 `film:`、`标题：`、`描述：`、`话题：`、`BGM：`，才能渲染。55 部已发布影片没有台账、也无法重建——台账从这里开始，好让平台的问题能用证据回答而不是靠回忆。`tests/upload-ledger.test.ts` 和 `npm run check` 强制这个文件及其字段；值本身可以在文案写好之前留空。
  门禁不只查字段**存在**，还查字段**写了什么**：`checkLedgerCopy` 用与片内同一张违禁词表扫 `标题：`/`描述：`/`话题：`，再叠上账号定位词。这不是多余的谨慎——视频号的处罚是落在标题和描述上的，不是落在某一帧上，所以只扫画面会放出一部画面合规、标题不合规的片。另外 `checkTitleFrames` 跨片比较标题框架（药名与「」里的词视作槽位），两条标题若是同一句话换了个名词，`npm run check` FAIL——这条规则单看一部片永远看不出来。`BGM：` 行也会被核对：它在建片时按当时的内容模块写死，之后改配乐就会静默失真，而台账是「母版到底配了什么」的唯一记录，所以它必须被查、不能被信。
- **母版与发布版本**：母版里烤进了本地 BGM，**工作流假定**上传时会用平台曲库替换，所以母版与线上视频并不逐字节相同。这个假定本身没有被验证过——在确认之前，不要拿它当论据（比如「换曲库对线上观感没有影响」）。把平台曲目记进台账，并把 `out/` 在 Git 之外另存一份（`npm run manifest` 记录那里应该有什么）。
- **曲库没有授权记录。** 图片有 `public/images/credits.json` 和背后的门禁；音乐只有 `src/music-registry.ts` 记了 `source`，`license` 全是 `unrecorded`。`npm run check` 每次都会把这行打出来。**不要凭猜测填一个许可证**——一个已被平台判罚的账号是最不该猜的地方。
- **封面**：**第 0 帧是一张空白纸**——入场动画从第 2 帧才开始淡入，所以第 0 帧只有纸面、山水和角落标签，没有标题、没有配图。平台上不要用默认首帧当封面；选 hero 完全出现之后的一帧（约第 3 秒，30 fps 下即第 90 帧往后），那一帧才有药名、拼音、部类、配图、原文摘录和别名。

```text
标题：麻黄为何称"龙沙"？

描述：
《神农本草经》卷二如何记载麻黄？
本片照录原文，逐句今译，附麻黄植株照片。
古籍内容展示，不构成诊疗建议。
#麻黄 #神农本草经 #本草 #中草药
```

## 验证

选条目时：`npm run entry -- --name=<条目>` 读经文并报出截断与掉字，`npm run variants` 报出讹字候选。三类残缺任一条命中，就换条目或按上文补字/采他本读法，不要带着一处可疑的字进入生产。

1. 先写一支专门的测试，跑到它为缺失的行为而失败。
2. 做最小的改动，然后跑 `npm test` 和 `npm run lint`。
3. 跑 `npm run check`（或 `npm run check -- --film=<CompositionId>`）。它执行合规规则、重复文本扫描、`产地` 与经文的核对，以及上传台账检查。任何一项不过的新片都不能渲染。`draft` 一行不算失败：它表示占位符还没清，在清完之前该片不可渲染。已经上线的片子只报告不判失败——它撤不回来，判决没有意义。
4. 跑 `npm run verify -- --film=<CompositionId>`：它把规则检查作为前置重跑一遍（并拒绝草稿），把 hero/source/closing 静帧渲染到 `out/stills/`，导出 `out/<name>.mp4`，并通过 `npx remotion ffprobe` 断言容器事实——1080x1920、30fps、H.264 视频、AAC 音频、时长与 Composition 一致、文件大小合理。三个静帧的帧位取自计划，所以无论场景数多少都是真正的场景中点。加 `--sheet`（可选 `--sheet=20`）可以改为采样接触表；360 帧里抽 3 帧，对一部主要失效模式是中段文字拥挤的影片来说样本太薄。
5. 静帧要你自己看：主体、印章、拼音、英文、中文在手机上的可读性；脚本替你判断不了。把新片的 hero 和 closing 与一部冻结影片的同帧位对比——这是唯一可靠的办法，能发现偏离系列视觉语言的地方。
6. 刷新 Studio，让最终 Composition 保持可预览。

## 已发布影片是冻结的

`scripts/lib/frozen-films.ts` 列出了已经发到平台上的影片。它们是冻结的：母版就是线上副本，所以本文档的规则**不会**回套到它们身上，它们已知的缺口只作信息报告。

- 永远不要往这个名单里加新片。新片必须满足当前规则。
- 名单只减不增，且只能通过退役一部影片并重制来减少。
- `tests/compliance.test.ts` 断言该名单与已发布影片完全一致，所以误加一部会让测试套件失败。

## 禁止事项

- 代码绘制的药物插图、把参考图当背景、或未授权/未署名的网络图片。
- 为了塞进更多材料而把拼音、英文、标签或原文做得极小。
